# 评审问题闭环记录

> 对应评审：`docs/2026-11-26-当前实现评审与改进建议.md`
> 处理日期：2026-11-26
> 验证环境：x86_64 Linux，GCC，`-fno-exceptions -fno-rtti -Wall -Wextra -Werror -Wpedantic`

## 0. 结论

P0 六项中五项已闭环（P0-6 测试隔离由 E2E worker 收尾，见 §3）；x86 4 Mbps 压测又发现并修复 P0-7（UDP 令牌桶丢 AU 导致活锁）。P1 十项中八项已处理，余下两项是明确的数据路径重构（TCP iovec）与平台验收（ARM 交叉/板测），按评审 §8 的阶段 4/5 保留。

当前 `ctest` 10/10 通过；真实 x264/x265 流经 ffmpeg 的 TCP/UDP 解码均为 rc=0；手动 RTSP 会话验证了 `interleaved=2-3` 有媒体、UDP `server_port` 为连续偶数对、TCP RTCP channel 上可见 SR（PT=200）。

## 4. 本轮验证命令与结果

```text
cmake --build build -j8
ctest --test-dir build --output-on-failure
=> 10/10 passed（含 test_e2e 26.5 s）

# 真实流解码（x264/x265 各 4 s，TCP 与 UDP）
ffmpeg -rtsp_transport {tcp,udp} -i rtsp://127.0.0.1:19560/live -frames:v 25 -f null -
=> h264_tcp rc=0, h264_udp rc=0
=> h265_tcp rc=0, h265_udp rc=0

# 手动 RTSP 会话
SETUP interleaved=2-3 -> 200, Transport 回显 interleaved=2-3
=> 收到 channels [2, 3]，channel 3 上 PT=200 (SR)
SETUP RTP/AVP;unicast;client_port=5000-5001 -> server_port=42308-42309
=> pair_ok True（偶数 + RTCP=RTP+1）
```

## 5. 剩余风险

1. TCP 媒体仍整段复制（P1-2），16 路 CPU 需实测后再决定是否做 iovec 发送。
2. UDP RTCP 接收未注册 fd watcher，客户端 RR 只在 TCP 传输下被解析；UDP 只发 SR。
3. 参数集运行期变更（SPS/PPS 热切换）仍未处理。
4. ARMv7 的 32 位 `uintptr_t` tag、对齐、长稳与温升未验证；x86 结论不能替代板测。
5. 无鉴权/无 TLS，仅允许可信网络部署。
